# Согласие при подаче заявки

`lib/pd-consent.ts` — общий источник текста галочки, версии согласия и версии
связанной Политики. Галочка изначально не отмечена. Форма отправляет `pdConsent`
и скрытое `pdConsentVersion`. API требует положительное согласие и точное
совпадение версии; при отсутствии/устаревании версии возвращает 422
`consent_version`, форма предлагает обновить страницу и дать согласие заново.

После проверки сервер создаёт `consent`: `accepted: true`, `method: checkbox`,
`requestId`, `acceptedAt` (UTC ISO — момент получения согласия сервером),
`version`, `text`, `policyUrl`, `policyVersion`. Значения даты, текста и прочие
метаданные из тела браузерного запроса игнорируются. Время клика не заявляется
достоверно установленным. IP и User-Agent в свидетельство не добавляются.

CRM сохраняет свидетельство в `WebsiteLeadConsent`, связанном с конкретной
сделкой. Company, Contact, Deal и согласие записываются одной транзакцией.
Сайт показывает успех только при `ok: true` и `consentSaved: true` от CRM.
При сбое данные остаются в форме. В Telegram/логи свидетельство не передаётся.
Повторная заявка получает отдельное согласие; редактирование сделки его не меняет.
Для старых заявок записи отсутствуют: миграция ничего не заполняет задним числом.

В CRM владелец/сотрудник с правом просмотра конфиденциальных данных видит
сведения в карточке компании, в разделе «Согласия на обработку данных».
Удаление сделки/компании удаляет связанное свидетельство по внешнему ключу.
Личный кабинет не получает внутренние сведения о согласиях через API статусов.

## Изменение редакции

При изменении текста галочки **или** Политики увеличивать `PD_CONSENT.version`;
при изменении Политики также обновлять `policyVersion` и `CONTACTS.policyUpdated`.
Выданные версии не переиспользовать. Полный исходник редакции Политики
`2026-09-11` сохранён в Git: `cf9a987:app/confidentiality/page.tsx` и
`cf9a987:lib/site.ts`. Снимок текста галочки хранится непосредственно в CRM.
Cookie-уведомление и согласие формы входа имеют отдельное назначение;
этот контракт относится к заявкам.

## Выкладка и проверка

Сначала применить миграцию и поддержку свидетельств в CRM с совместимостью
со старым сервером сайта. Затем выкатить сайт, который требует подтверждения
сохранения согласия. После обновления сайта отключить в CRM старый формат
заявки без свидетельства. Не выдавать старую заявку за согласованную.

`npm run test:lead` проверяет отказ без галочки/версии, подмену метаданных,
передачу свидетельства и обязательное подтверждение CRM. Браузерная проверка
`tests/csp.browser.cjs` подменяет доставку заявки: писем, Telegram-уведомлений
и клиентских записей не создаёт. Интеграционный тест CRM выполняется отдельно
с явно заданной изолированной PostgreSQL и проверяет сохранение и откат.
