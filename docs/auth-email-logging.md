# Отправка ссылок входа и журналы

В production и при любом `NODE_ENV`, кроме `development`, для запроса ссылки
нужен почтовый транспорт: `UNISENDER_API_KEY` либо `SMTP_HOST`. Пробельные значения
считаются пустыми. Остальные настройки транспорта описаны в [DEPLOY.md](../DEPLOY.md).

Если транспорт не задан, общий `callbacks.signIn` отклоняет запрос до создания
токена и расходования квоты. Это действует для формы `/lk` и стандартного
`/api/auth/signin/email`. Пользователь видит предложение повторить попытку позже.
Проверка настройки отправки не мешает открывать уже выданную ссылку.

Ответ почтового сервиса должен подтверждать приём. При отказе транспорта
успешная отправка не показывается; квота запроса остаётся израсходованной.
Auth.js может уже сохранить токен до отказа почты, но ссылка не выводится в лог.

В production Auth.js пишет только технический тип ошибки либо один из кодов:

- `AUTH_EMAIL_UNCONFIGURED` — транспорт не задан;
- `AUTH_EMAIL_HTTP_UNREACHABLE` — ошибка обращения к Unisender Go;
- `AUTH_EMAIL_HTTP_REJECTED` — сервис не подтвердил приём;
- `AUTH_EMAIL_RECIPIENT_REJECTED` — адрес отклонён;
- `AUTH_EMAIL_SMTP_FAILED` — сбой SMTP.

Сообщения исключений, вложенные причины, ответы почтового сервиса, адреса,
ссылки и отладочные метаданные Auth.js не выводятся. Консольная ссылка без
почты и предпросмотр Ethereal доступны только при `NODE_ENV=development`.

`npm run test:auth` проверяет оба способа запроса, отсутствие транспорта,
HTTP- и SMTP-ошибки, успешную отправку, отсутствие секретов в журналах
и сохранение локального режима разработки. Почта и база в этих сценариях
подменены; реальные письма не отправляются. Отдельный тест PostgreSQL
запускается при заданном `AUTH_TEST_DATABASE_URL`.
