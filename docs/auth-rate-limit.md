# Ограничение отправки ссылок входа

Проверка выполняется в общем `callbacks.signIn` Auth.js при
`email.verificationRequest`, до создания токена и отправки письма. Она действует
и для Server Action формы `/lk`, и для стандартного `/api/auth/signin/email`.
Переход по уже выданной ссылке не расходует лимит отправки.

- До 5 разрешённых запросов с одного IP за 15 минут.
- До 3 разрешённых запросов на один нормализованный адрес за 15 минут.
- Счётчики находятся в PostgreSQL и общие для всех процессов приложения.
- Проверка и увеличение обоих счётчиков выполняются в одной транзакции.
  При отказе по любому лимиту оба изменения откатываются.
- Окно начинается с первого разрешённого запроса. Повторные запросы не
  продлевают окно. Ошибка почтового сервиса не возвращает израсходованную квоту.
- При ошибке базы запрос блокируется. Пользователь получает сообщение о повторе
  позже, сервер пишет техническую метку `AUTH_RATE_LIMIT_UNAVAILABLE` без контактов.
- В таблице хранятся HMAC-ключи, счётчик и время истечения. При запросах небольшими
  порциями удаляются истёкшие записи.

## Развёртывание

Миграция `20260913130000_auth_rate_limit` добавляет таблицу `AuthRateLimit`
и индекс срока действия. Существующие таблицы и заявки не изменяются.
`docker-entrypoint.sh` уже применяет миграции перед запуском приложения.
При другом способе запуска сначала выполнить `prisma migrate deploy`.
Без новой таблицы отправка ссылок будет блокироваться.

Новые сервисы и переменные окружения не нужны: используются существующие
`DATABASE_URL` и `AUTH_SECRET` (резервное имя — `NEXTAUTH_SECRET`). Секрет должен
быть одинаковым на всех экземплярах; его смена изменяет ключи счётчиков.
IP определяется существующей функцией `clientIpFromHeaders`; приложение должно
получать соответствующие заголовки от доверенного обратного прокси.

## Проверка

`npm run test:auth` проверяет оба пути Auth.js, оба почтовых транспорта, отказ
по лимиту и при сбое базы. Внешняя почта в тестах подменена.

Для проверок конкурентности задать `AUTH_TEST_DATABASE_URL` на тестовую PostgreSQL
и выполнить `npm run test:auth` или полный набор `npm run test:lead`.
Тест создаёт отдельную схему со случайным именем и удаляет её по завершении.
Он не читает `.env` и не использует `DATABASE_URL` приложения.

На изолированной PostgreSQL проверено: 20 одновременных запросов пропускают
ровно 3 обращения на адрес или 5 с IP, новые экземпляры обработчика видят общие
счётчики, истёкшие окна открываются заново, действующие ограничения сохраняются.

Также проверена собранная версия Next.js с настоящим Prisma: прямой запрос
блокируется при исчерпанной квоте, разрешённый создаёт один токен, форма в браузере
показывает отказ и сохраняет введённый адрес. Внешняя отправка почты была отключена.
