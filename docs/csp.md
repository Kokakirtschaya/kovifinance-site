# Content Security Policy

`proxy.ts` выдаёт принудительную `Content-Security-Policy` для страниц, ответов
404, переходов RSC и HTML Auth.js. Для каждого ответа генерируется новый nonce
из 16 криптографически случайных байтов. Входящие заголовки CSP и `x-nonce`
заменяются серверными значениями, в том числе при prefetch.

Next.js получает ту же политику в заголовке запроса и добавляет nonce к своим
скриптам. JSON-LD на главной получает его явно. Скрипты без разрешающего nonce
или доверенной цепочки загрузки, обработчики в HTML-атрибутах и `eval` блокируются.
Это соответствует [механизму nonce в Next.js](https://nextjs.org/docs/app/guides/content-security-policy).

Политика находится в `lib/csp.ts`:

- соединения браузера, шрифты и отправка HTML-форм разрешены на свой домен;
- изображения разрешены со своего домена и через `data:`;
- запрещены фреймы, плагины, встраивание сайта во фрейм и изменение базового URL;
- inline CSS разрешён для атрибутов React и динамических стилей Motion;
- только в development разрешены `eval` и WebSocket для HMR.

CRM, Checko, Telegram и почта вызываются сервером и не требуют добавления их
доменов в браузерную политику. Ссылки на соцсети открываются обычной навигацией.

## Генерация и кэширование

Корневой layout вызывает `connection()`: HTML формируется на каждый запрос,
чтобы nonce не повторялся из статического кэша. HTML/RSC имеют `private, no-store`.
Это увеличивает работу сервера относительно прежней статической генерации.
Каталоги изображений, шрифты, JS/CSS Next.js и метаданные исключены из proxy;
их обычное кэширование сохраняется. При добавлении CDN нельзя кэшировать HTML
с одним nonce для разных запросов.

## Проверка

`npm run test:lead` включает проверки политики, смены nonce, перезаписи
поддельных заголовков и охвата маршрутов. Браузерная проверка запускается отдельно
при наличии Playwright с установленными Chromium и WebKit:

```sh
PLAYWRIGHT_MODULE=/absolute/path/to/playwright node tests/csp.browser.cjs https://localhost:3443 --report-only
PLAYWRIGHT_MODULE=/absolute/path/to/playwright node tests/csp.browser.cjs https://localhost:3443
```

Адрес должен вести на production-сборку по HTTPS. `--report-only` меняет заголовок
только внутри тестового браузера, не меняя политику сервера. Сначала проверяется
совместимость, затем реальная блокировка внедрённого кода и внешнего соединения.
Проверяются калькулятор, формы, переходы RSC, 404 и соответствие nonce в HTML.
CRM и Checko подменены в браузере; запрос входа использует некорректный адрес,
который сервер отклоняет до обращения к Auth.js. Заявки и письма не создаются.
