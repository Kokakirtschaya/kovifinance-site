# Переезд сайта kovifinance.ru на Timeweb — подробная инструкция

Пошаговый гайд «клик за кликом». Помечено:
- **[ТЫ]** — делаешь руками в панели Timeweb / Tilda / Госуслуги.
- **[Я]** — правки в коде, готовит Claude в этом репозитории.

Главное правило безопасности: **DNS переключаем в самом конце**. Пока он смотрит на
Тильду — старый сайт работает, клиенты ничего не замечают. Если новый прод сломается,
просто не переключаем DNS.

Что у нас будет на Timeweb:
1. **Домен** kovifinance.ru — регистратор Timeweb (перенос с Tilda Domains).
2. **Managed PostgreSQL** — база аккаунтов личного кабинета (152-ФЗ: данные в РФ).
3. **Cloud App** — само приложение Next.js, деплоится из GitHub по Dockerfile.

Ссылки на панель: https://timeweb.cloud/ (Cloud — Apps и БД) и
https://timeweb.com/ (домены/регистратор). Это два раздела одного аккаунта.

## Этап 1. Перенос домена kovifinance.ru: Tilda → Timeweb  **[ТЫ]**

Это перенос **регистрации** домена (не хостинга). Причина — требование идентификации
владельца через Госуслуги (в реестре домен сейчас `UNVERIFIED`); Timeweb это закрывает.

⚠️ **Особенность нашего случая (проверено 2026-07-20):** DNS домена сейчас обслуживают
**серверы Тильды** — `ns1.tildadns.com` / `ns2.tildadns.com`. Значит и запись сайта, и все
записи почты Яндекса настроены В ПАНЕЛИ ТИЛЬДЫ. Если просто увести регистратора, Тильда
может перестать отдавать DNS → сайт И почта лягут одновременно. Поэтому порядок такой:
**сначала переносим DNS на Timeweb, и только потом — регистратора.**

|---|---|---|---|---|
| A | `@` | `176.57.65.207` | — | 900 |
| CNAME | `www` | `kovifinance.ru.` | — | 900 |
| MX | `@` | `mx.yandex.net.` | `10` | 900 |
| TXT | `@` | `v=spf1 include:_spf.yandex.net ~all` | — | 900 |
| TXT | `mail._domainkey` | `v=DKIM1; k=rsa; t=s; p=MIGfMA0GCSqGSIb3DQEBAQUAA4GNADCBiQKBgQDQ+ZgmBhmNH9dql6vSBgUMaOJu1lhPD3AekuY9xxKNvt1PviuSvuff+Z6E0ERRBLYmqqEBndjOuNzTTg8pQNkj4WU5m0MtlK8hYNccfZ3ul0BtmATo51xJ2PiAewbgoP1FP6JIDqmXpDjaKmleDI1R/7QS31KENaJ6+q8QtCbdCQIDAQAB` | — | 900 |
| TXT | `_dmarc` | `v=DMARC1; p=none; rua=mailto:info@kovifinance.ru,mailto:r.zakirov@kovifinance.ru` | — | 900 |

Правки против версии 2026-07-20: `www` — это **CNAME** на `kovifinance.ru.`, а не A-запись с IP.
DKIM = 240 символов, влезает в одну TXT-строку (лимит 255) — разбивать не нужно.

⚠️ **`dig` показывает только то, что мы спросили.** Источник истины — **панель Тильды**:
там могут быть записи, о которых мы не знаем (проверочные TXT Яндекса, поддомены,
`CAA`). Открыть список записей в Тильде и переписать **все** — таблица выше только
для сверки. Проверено: `CAA`, `AAAA`, `mail`, `webmail`, `autodiscover`,
`yandex._domainkey`, `_domainconnect` — пусты.

A-запись `176.57.65.207` пока оставляем на Тильду (сайт живёт там до этапа 7).

### 1.1. Создать DNS-зону в Timeweb и продублировать ВСЕ записи

1. https://timeweb.cloud/ → раздел **«Домены»** (или «DNS»).
2. Добавить `kovifinance.ru` как **внешний домен** — он зарегистрирован не в Timeweb,
   нужен режим «домен у другого регистратора / только управление DNS». Если такого
   пункта в интерфейсе нет — написать в поддержку Timeweb, сценарий стандартный.
3. **Удалить автоматически созданные записи-заглушки.** Timeweb при создании зоны обычно
   заводит свои A/CNAME на парковку — если их оставить, после смены NS сайт уедет на
   заглушку Timeweb вместо Тильды.
4. Внести все записи из таблицы 1.0. На что смотреть:
   - в поле «значение» MX и CNAME — **точка в конце** (`mx.yandex.net.`), иначе панель
     достроит имя до `mx.yandex.net.kovifinance.ru`;
   - MX-приоритет `10` — отдельное поле;
   - имя хоста для DKIM — ровно `mail._domainkey` (панель сама допишет домен);
   - SPF/DKIM/DMARC вводить **без внешних кавычек** — панель добавит их сама.
5. Записать выданные Timeweb имена его NS-серверов — они показаны в свойствах зоны
   (обычно вида `ns1.timeweb.ru`, `ns2.timeweb.ru`, `ns3.timeweb.org`, `ns4.timeweb.org`,
   но брать **ровно те, что показала панель**, а не эти).

**Проверка ДО переключения** — можно спросить сервер Timeweb напрямую, он ответит из
новой зоны, хотя делегирование ещё на Тильде. Подставить свой NS из шага 5:

```bash
NS=ns1.timeweb.ru   # ← имя из панели
dig @$NS kovifinance.ru A     +noall +answer
dig @$NS www.kovifinance.ru   CNAME +noall +answer
dig @$NS kovifinance.ru MX    +noall +answer
dig @$NS kovifinance.ru TXT   +noall +answer
dig @$NS mail._domainkey.kovifinance.ru TXT +noall +answer
dig @$NS _dmarc.kovifinance.ru TXT +noall +answer
```

Ответы обязаны совпадать с таблицей 1.0 **до символа**. Пока не совпали — NS не трогать.

### 1.2. Сменить NS у домена на Timeweb (в панели Тильды)

1. Личный кабинет Tilda → **«Домены»** → `kovifinance.ru` → настройки **NS / DNS-серверы**.
2. Заменить `ns1.tildadns.com` / `ns2.tildadns.com` на NS Timeweb из шага 1.1
   (внести **все** выданные, не два из четырёх).
3. Ждать делегирование: обычно 15 мин – 4 ч, по регламенту до 24 ч.

**Как понять, что переключилось** (реестр .RU — источник истины):

```bash
whois kovifinance.ru | grep nserver     # должны быть NS Timeweb
dig NS kovifinance.ru +short            # то же, но из кеша резолвера
```

4. **Проверить, что ничего не отвалилось:**
   - `curl -sI https://kovifinance.ru | head -1` → сайт на Тильде по-прежнему отвечает;
   - `dig kovifinance.ru MX +short` → `10 mx.yandex.net.`;
   - **письмо снаружи на `info@kovifinance.ru` дошло** (с личной почты, не с домена);
   - **письмо из `info@kovifinance.ru` наружу ушло** и в заголовках получателя
     `spf=pass` и `dkim=pass` (в Gmail: «Показать оригинал»).

Пока пункт про почту не проверен — **дальше не идти**. Это единственный шаг, где можно
уронить почту, и чинится он мгновенно только пока помнишь, что менял.

**Откат:** вернуть в Тильде прежние NS `ns1.tildadns.com` / `ns2.tildadns.com`.
Зона Тильды никуда не делась, всё вернётся за то же время делегирования.

После успеха DNS больше не зависит от Тильды — можно спокойно переносить регистратора (1.3).

### 1.3. Перенести регистратора Tilda → Timeweb (.RU)
Для .RU процедура — «смена регистратора» (не всегда через auth-code, как у .com):
1. В Tilda: снять запрет на передачу (Transfer Lock), если стоит; при наличии — получить
   код передачи. Если опции нет — написать в **поддержку Tilda** с просьбой разрешить
   смену регистратора на Timeweb.
2. Убедиться, что доступна почта администратора домена (придёт подтверждение).
3. В Timeweb: https://timeweb.com/ → «Домены» → **«Перенести/сменить регистратора»** →
   ввести `kovifinance.ru`, следовать шагам.
4. Подтвердить перенос по письму.
5. Пройти **идентификацию владельца через Госуслуги (ЕСИА)** — снимет статус `UNVERIFIED`.
6. Оплатить (обычно = продление на +1 год).

> DNS уже на Timeweb (этап 1.2), поэтому смена регистратора на сайт и почту не влияет.
> Перенос .RU идёт до 5 суток; всё это время всё работает.

> Перенос идёт от нескольких часов до 5 суток. Всё это время старый сайт работает.

## Этап 2. Managed PostgreSQL  **[ТЫ]**

Локально база — SQLite. На проде по 152-ФЗ нужен Postgres в РФ.

1. https://timeweb.cloud/ → **«Базы данных»** → **«Создать»**.
2. Тип: **PostgreSQL** (свежая версия, напр. 16). Регион — **Россия** (Москва/СПб).
3. Тариф — минимальный стартовый (потом можно поднять).
4. Задать имя кластера, напр. `kovi-db`.
5. После создания открыть кластер → вкладка **«Подключение»**:
   - создать **базу данных** (напр. `kovi`) и **пользователя** (напр. `kovi_app`) с паролем;
   - скопировать **строку подключения** вида:
     `postgresql://kovi_app:ПАРОЛЬ@HOST:5432/kovi?sslmode=require`
6. В настройках доступа кластера разрешить подключение с будущего App
   (внутренняя сеть Timeweb или белый список IP — Timeweb подскажет в интерфейсе).

**Что дальше со строкой:** её задашь как переменную `DATABASE_URL` в настройках App
(этап 5). Мне её показывать не обязательно — если пришлёшь, я проверю формат.

## Этап 3. Перевод кода на PostgreSQL + Docker  **[Я]**

Сделано в репозитории (2026-07-26):
- `prisma/schema.prisma`: провайдер `sqlite` → `postgresql`.
- `lib/prisma.ts`: адаптер `better-sqlite3` → `@prisma/adapter-pg`.
- `package.json`: убран `better-sqlite3`, добавлены `pg` + `@prisma/adapter-pg`.
- **`Dockerfile`** — multi-stage: `next build` со standalone-выводом, старт `node server.js`.
- **`docker-compose.yml`** — локальный Postgres 16 для разработки (заменил `dev.db`).
- **`docker-entrypoint.sh`** — при старте контейнера прогоняет `prisma migrate deploy`,
  так что схема на проде догоняется сама и об этом нельзя забыть.
- Старая SQLite-миграция удалена, `init` пересоздана под Postgres.

⚠️ После этого локальная разработка идёт на Postgres (`docker compose up -d`), а не на SQLite.

**Грабли, выясненные по дороге:**
- В Prisma 7 `url` в блоке `datasource` **больше не поддерживается** (ошибка P1012) —
  строка подключения только в `prisma.config.ts`. Поэтому в рантайм-образ едут
  `prisma.config.ts`, Prisma CLI и `dotenv`, иначе миграции при старте не запустятся.
- `app/opengraph-image.tsx` читает шрифт из `assets/` **в рантайме** через
  `process.cwd()`. Трассировка Next такой путь не видит, в standalone файл не попадает —
  в `Dockerfile` папка копируется явно, а в `.dockerignore` она НЕ исключена.
- Standalone не кладёт `public` и `.next/static` — копируются отдельными слоями,
  иначе сайт поднимется без картинок и JS.

## Этап 5. Переменные окружения на проде  **[ТЫ вводишь в панели App]**

В настройках App → раздел «Переменные окружения» (Environment variables):

| Переменная | Значение |
|---|---|
| `DATABASE_URL` | строка Postgres из этапа 2 |
| `AUTH_SECRET` | **новый** секрет: сгенерировать `openssl rand -base64 32` (НЕ из локалки) |
| `AUTH_URL` | `https://kovifinance.ru` |
| `CRM_API_URL` | `https://crm.koka-net.ru` |
| `CRM_API_TOKEN` | = `PUBLIC_API_TOKEN` в CRM |
| `TELEGRAM_BOT_TOKEN` | токен бота (чтобы заявки уходили в TG) |
| `TELEGRAM_CHAT_ID` | id чата для заявок |
| `CHECKO_BASE_URL` | как в локальном `.env` |
| `CHECKO_API_KEY` | как в локальном `.env` |
| `SMTP_HOST` | `smtp.yandex.ru` |
| `SMTP_PORT` | `465` (SSL) |
| `SMTP_USER` | `info@kovifinance.ru` |
| `SMTP_PASSWORD` | **пароль приложения** Яндекса (не обычный пароль!) |
| `EMAIL_FROM` | `info@kovifinance.ru` |

Значения `CRM_*`, `TELEGRAM_*`, `CHECKO_*` возьмём из текущего локального `.env`.

**Почта для входа в ЛК — решено: Яндекс 360.** Почта kovifinance.ru уже на Яндексе,
используем его SMTP. Свой почтовый сервер не нужен.
- Пароль приложения создаётся в **Яндекс ID → Безопасность → Пароли приложений** (тип «Почта»).
  Обычный пароль от ящика для SMTP не подойдёт.
- Локально отправку не проверить (домашний DPI режет SMTP), но **с прод-сервера Timeweb
  (РФ) Яндекс-SMTP работает** — проверяем на проде.

Без рабочей почты **сайт и форма заявок поедут** — от почты зависит только вход в ЛК.

## Этап 7. Переключение DNS — ПОСЛЕДНИЙ шаг  **[ТЫ]**

Только после того, как временный домен полностью прошёл проверку из этапа 6.

1. В App/домене Timeweb выпустить **SSL** для kovifinance.ru (Let's Encrypt, обычно в 1 клик).
2. Привязать домен kovifinance.ru к App.
3. В DNS-зоне переключить записи **A/CNAME** с Тильды на Cloud App
   (значение даст Timeweb при привязке домена к приложению).
4. Подождать, пока DNS разойдётся (до ~1 часа).
5. **Тильду НЕ выключать**, пока не убедишься вживую, что kovifinance.ru отдаёт новый сайт
   по HTTPS и всё из этапа 6 работает.
6. Через 1–2 дня стабильной работы — можно отключать старый сайт на Тильде.

**Откат:** если после переключения что-то сломалось — вернуть DNS-записи на прежние
(тильдовские) значения, сайт вернётся на Тильду.
